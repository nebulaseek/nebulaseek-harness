# Agent Note：NebulaSeek（星云寻知）品牌覆盖层

状态：已实施

[English](2026-09-22-nebulaseek-brand-overlay.md) | 中文

## 问题

本发行版需要向用户展示星云寻知品牌，同时持续以较小冲突同步 DeepSeek Harness 社区版。如果重命名包作用域、环境变量、命令、持久化标识或插件契约，一次展示层调整就会变成对上游运行时行为的长期分叉。

## 决策

保留社区代码和技术契约，仅在实际交付的用户可见界面应用下游品牌：侧边栏和会话首页、浏览器元数据、桌面应用及安装器文案、图标、CLI 描述、引导和错误文案，以及公开仓库 README。

英文产品名为 `NebulaSeek（星云寻知） Harness`，简体中文使用 `星云寻知`。命令仍为 `dsh`，包作用域仍为 `@deepseek-ai/*`，环境变量仍为 `DSH_*`，上游插件、存储、协议和服务标识保持不变。DeepSeek 模型名称和社区上游名称也继续使用 DeepSeek。

当资源文件名属于内部构建输入时，品牌资源保留上游文件名。官方品牌插件统一提供侧边栏和会话首页标识，通用 UI 包无需下游修改。

## 上游同步流程

1. 拉取社区远程仓库，将下游分支重置或变基到选定的上游提交。
2. 重新应用单一的星云寻知品牌提交，只在本文记录的展示层文件中解决冲突。
3. 检查差异中是否出现展示层以外的修改，并移除意外的内部重命名。
4. 发布下游提交前，运行品牌、语言、打包、类型和文档的针对性检查。

## 备选方案

**全仓库替换 DeepSeek Harness。** 不采用，因为这会改动技术契约并持续制造同步冲突，却不会增加用户可见价值。

**重命名包作用域、命令、环境变量和持久化标识。** 不采用，因为这些名称是插件、脚本、已有数据和 Desktop 共同依赖的兼容边界。

**维护一份通用 UI 组件副本。** 不采用，因为上游插槽系统已经提供了发行版品牌的单一归属位置。

## 影响

用户会在发行应用中看到星云寻知，插件和集成仍继续使用上游契约。后续同步通常只需处理这个覆盖层，以及上游新增的用户可见界面。如果上游调整技术标识，应将其作为上游迁移采用，而不是混入品牌修改。

## 测试

官方品牌插件测试覆盖侧边栏和会话首页注册以及文字标识渲染。语言、安装器、清单、打包和引导测试固定其他可见名称。类型检查和文档配对门禁保护共享接口与双语规范记录。
